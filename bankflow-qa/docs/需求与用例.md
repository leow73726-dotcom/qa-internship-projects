# 需求到测试的映射

先把业务预期写清，再用自动化判断。下面是测试分组，不是代码行覆盖率。

| 需求 ID | 预期行为 | qa/ 中的测试函数 |
| --- | --- | --- |
| FIN-01 | 演示账号登录与账户结构正确 | `test_demo_login_and_account_contract` |
| FIN-02 | 正常转账双方余额及总额正确 | `test_transfer_conserves_total_and_changes_both_balances` |
| FIN-03 | 转账生成配对借贷流水 | `test_transfer_creates_matching_debit_and_credit_entries` |
| FIN-04 | 存款、取款十进制金额正确 | `test_decimal_deposits_are_exact / test_withdraw_changes_balance_by_exact_amount` |
| FIN-05 | 练习新增规则：只接受正金额、最多两位小数且不缺失 | `test_transfer_policy_rejects_invalid_amount_without_writes / test_missing_amount_is_rejected` |
| FIN-06 | 练习新增规则：不能转给自己 | `test_same_account_transfer_is_rejected` |
| FIN-07 | 不存在目标账户时余额与流水回滚 | `test_failed_destination_rolls_back_debit_and_ledger` |
| FIN-08 | 按金额筛选流水 | `test_transaction_amount_filter` |

执行步骤：停掉手动实例→运行 test.cmd→查看 results.xml→失败时保留现场。每个参数化输入算一个测试实例。`reports/cases.csv` 从最后一次 JUnit 报告生成，记录逐例结果。

未覆盖项：金融演示系统，不代表真实金融生产经验；不使用上游可选的商业测试工具或相关许可配置。
