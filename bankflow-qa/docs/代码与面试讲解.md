# 先读代码，再练习讲解

它是一家虚拟银行。账户余额、存款、取款和转账都是演示数据。你的重点是检查：转账前后双方余额是否变化正确、总金额是否守恒、是否产生配对流水，以及转账失败会不会只扣钱却没到账。

阅读顺序：先看 qa/test_*.py 的输入和 assert，再看 qa/conftest.py 的数据与环境准备，最后定位 Java 控制器或页面操作。拿一个用例画出“准备→执行→断言→清理”，可以比只背术语更快理解。

## 1. 转账成功怎么判断？

除了 HTTP 200，还要核对 A 减少 x、B 增加 x、A+B 总额不变，并检查新产生的 Debit/Credit 两条流水金额一致。

## 2. 为什么用 Decimal？

二进制浮点数不适合直接断言十进制钱数。这里用字符串构造 Decimal，并让 JSON 小数也按 Decimal 解析，避免测试本身引入误差。

## 3. 怎么测回滚？

给一个不存在的目标账户转账，断言请求失败，再查询原账户余额和流水数量都不变。它验证的是当前实现下的外部可观察结果。

## 4. 零金额等原来都算 Bug 吗？

这是个人扩展中先明确的练习需求。上游没有完全相同的约束，不能把新规则不满足全部说成上游缺陷；缺失金额原来返回 500 是单独的错误处理现象。

## 5. 数据库怎样隔离？

仅访问 localhost 的独立演示实例，每个用例 POST initializeDB 恢复固定初始账户。它不适合指向共享测试库。

## 6. 项目和真实银行还有什么差距？

没有完成并发压力、幂等、支付清算、真实风控或合规验证。演示系统部分 API 也不是生产级身份与权限设计。

## 英文项目介绍

Built a local banking API test exercise on ParaBank. Used Decimal assertions to check balance conservation, paired ledger entries and failed-transfer rollback, and added explicit transfer validation rules.

只有在你亲手复现、读懂并能现场修改后，才把这些表述作为自己的项目能力。当前文本是学习材料。
