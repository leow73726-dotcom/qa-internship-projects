# 需求到测试的映射

先把业务预期写清，再用自动化判断。下面是测试分组，不是代码行覆盖率。

| 需求 ID | 预期行为 | qa/ 中的测试函数 |
| --- | --- | --- |
| API-01 | 健康检查及接口文档可用 | `test_health_and_openapi` |
| API-02 | 主人创建、查询、修改、删除后再查 | `test_owner_create_read_update_delete` |
| API-03 | 非法电话号码返回 400 且不保存 | `test_invalid_phone_is_not_persisted` |
| API-04 | 姓名格式及长度边界 | `test_invalid_name / test_valid_name_boundaries` |
| API-05 | 主人—宠物—就诊关联一致 | `test_owner_pet_visit_business_flow` |
| API-06 | 错误主人路径不能读写宠物或新增就诊 | `test_nested_pet_cannot_be_read_through_different_owner / test_nested_pet_write_requires_matching_owner` |
| API-07 | 不存在资源返回 404 | `test_missing_resource` |
| API-08 | page=-1、size=0 返回 400 | `test_page_boundaries` |

执行步骤：停掉手动实例→运行 test.cmd→查看 results.xml→失败时保留现场。每个参数化输入算一个测试实例。`reports/cases.csv` 从最后一次 JUnit 报告生成，记录逐例结果。

未覆盖项：只验证本地 H2 默认配置，未验证 MySQL/PostgreSQL 或启用认证后的矩阵。
