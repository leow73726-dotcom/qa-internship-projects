# 实际问题与修复

基线：reports/baseline.xml，19 通过、4 失败。修改后结果见 results.xml。以下是在本地固定上游提交上的可复现现象，未向上游提交 Issue/PR。

## CLINIC-01：路径主人和宠物所属主人不一致仍可写入

前提：创建主人 A、B；给 A 创建宠物 P。

步骤一：PUT /api/owners/B/pets/P 修改名字。修改前返回 204，P 的名字被改变。
步骤二：POST /api/owners/B/pets/P/visits 添加就诊。修改前返回 201。

预期：与嵌套 GET 一样返回 404，宠物名字和就诊列表不变。每个步骤在独立测试数据中执行。

修复：OwnerRestControllerV1 对修改和新增就诊先检查 currentOwner.getPet(petId) 或 owner.getPet(petId)。回归覆盖两种写操作及读取，检查拒绝后无数据变化。

此项是资源关系一致性检查；默认认证关闭，因此不将它表述为已经验证账号权限隔离。

## CLINIC-02：非法分页输入返回 500

步骤：分别 GET /api/v2/owners?page=-1 和 ?size=0。

修改前：都返回 500；日志为 ConstraintViolationException。预期：客户端参数错误应返回 400。

修复：ExceptionControllerAdvice 增加 ConstraintViolationException → 400 的专用映射；控制器另有参数防御判断。只加控制器判断无法解决方法调用前的校验异常。

两项问题共触发 4 个失败测试实例；不能把“4 个失败实例”写成“4 个独立缺陷”。
