# 先读代码，再练习讲解

它是一个宠物诊所的后台服务：登记主人、登记宠物、记录就诊。这里没有完整的挂号网页，你通过 Swagger 或 Python 发送接口请求，检查数据库里的业务结果是否正确。

阅读顺序：先看 qa/test_*.py 的输入和 assert，再看 qa/conftest.py 的数据与环境准备，最后定位 Java 控制器或页面操作。拿一个用例画出“准备→执行→断言→清理”，可以比只背术语更快理解。

## 1. 为什么不只检查 200？

成功状态码不代表数据正确。创建后要核对返回 ID，再 GET 检查关联和字段；拒绝错误请求后还要验证数据没有被修改。

## 2. 边界值怎么选？

姓名允许 1 到 30 个字符，所以测空、1、30、31，并补充空格、数字和中文；电话号码测 9、10、11 位及非数字、空、null。

## 3. 怎么组织测试数据？

owner_factory 创建唯一姓氏的主人，记录 ID，测试后删除。每次启动 H2 都重新加载演示数据，不依赖上一次运行结果。

## 4. 嵌套接口的问题如何复现？

创建主人 A、B，给 A 添加宠物 P。使用 B 的路径去修改 P 或添加就诊。修改前分别返回 204、201；预期为 404 且 P 的名字和就诊记录不变。

## 5. 这算权限漏洞吗？

这里验证的是路径中的业务关系一致性。默认演示环境关闭身份认证，不能据此声称完成用户级鉴权或生产安全测试。

## 6. 分页为什么返回 500？

@Min 校验在进入控制器方法前抛出 ConstraintViolationException，原来的通用异常处理把它当 500。新增专门处理返回 400，保留统一错误结构。
