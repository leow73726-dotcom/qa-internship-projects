# 先读代码，再练习讲解

它是一个模拟购物网站。你可以登录、选商品、放进购物车、填写收货信息、完成结算。你要做的工作，是让程序像人一样操作浏览器，检查这些步骤有没有出错。它没有真实付款，也没有真实电商订单后端。

阅读顺序：先看 qa/test_*.py 的输入和 assert，再看 qa/conftest.py 的数据与环境准备，最后定位 Java 控制器或页面操作。拿一个用例画出“准备→执行→断言→清理”，可以比只背术语更快理解。

## 1. 这个项目测的是什么？

测模拟电商购物流程。输入是账号、商品选择、收货信息；输出是页面提示、购物车状态和结算金额。它不包含真实支付链路。

## 2. 为什么使用 Page Object？

pages.py 负责点击、输入、等待；test_storefront.py 负责判断业务结果。按钮定位变了，可以集中修改页面操作。

## 3. 为什么不能到处 sleep？

固定等待不能表达页面何时准备完成。这里等元素可见、可点击、路由切换和字体就绪，减少页面布局或异步渲染造成的误判。

## 4. 如何判断金额正确？

用 Decimal 表达 29.99 和 9.99，按示例税率计算并保留两位，再分别核对小计、税额和总价。没有用页面总价反推预期值。

## 5. 测试之间怎么隔离？

每个用例使用新的 Chrome 临时配置目录；结束时退出浏览器并清理配置，避免 cookie 或购物车状态串到下一个用例。

## 6. 失败后怎么定位？

先看 reports/results.xml 的失败步骤，再看 reports/failures 的截图、HTML、URL 和控制台日志，区分页面问题、定位问题与环境问题。

## 英文项目介绍

Built a local UI regression exercise on the Sauce Labs sample app, using Python, Selenium and Pytest. Separated page operations from assertions and checked login, sorting, cart state and checkout totals.

只有在你亲手复现、读懂并能现场修改后，才把这些表述作为自己的项目能力。当前文本是学习材料。
