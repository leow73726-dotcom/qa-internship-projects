# 需求到测试的映射

先把业务预期写清，再用自动化判断。下面是测试分组，不是代码行覆盖率。

| 需求 ID | 预期行为 | qa/ 中的测试函数 |
| --- | --- | --- |
| UI-01 | 可登录并显示六个商品 | `test_login_and_inventory` |
| UI-02 | 空账号、空密码、错误账号、锁定账号应提示错误 | `test_login_errors` |
| UI-03 | 按名称或价格升降序正确排序 | `test_sorting` |
| UI-04 | 购物车增删及刷新后状态正确 | `test_add_remove_and_reload_cart` |
| UI-05 | 结算三个必填项分别校验 | `test_checkout_required_fields` |
| UI-06 | 中英文姓名可结算且金额正确、购物车清空 | `test_checkout_totals_and_cart_cleared` |
| UI-07 | 匿名访问商品页跳回登录 | `test_anonymous_inventory_redirects_to_login` |

执行步骤：停掉手动实例→运行 test.cmd→查看 results.xml→失败时保留现场。每个参数化输入算一个测试实例。`reports/cases.csv` 从最后一次 JUnit 报告生成，记录逐例结果。

未覆盖项：前端模拟业务，不覆盖真实支付和服务端鉴权；UI 自动化依赖 Chrome 与驱动版本匹配。
